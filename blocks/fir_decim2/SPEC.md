# Spec: 25-tap symmetric decimate-by-2 polyphase FIR (RFSoC)

## Customer prompt (verbatim)

> A high-performance 25-tap symmetrical decimate-by-2 polyphase FIR filter implemented in SystemVerilog. The design is optimized for AMD RFSoC devices, utilizing DSP48 pre-adders to leverage coefficient symmetry and minimize resource usage while maintaining high throughput.

## Interface (answers given during `/s2r:new-project` questioning)

| Signal | Dir | Width | Notes |
|---|---|---|---|
| `clk` | in | 1 | one input sample per clock when `in_valid` |
| `rst_n` | in | 1 | async assert, sync de-assert |
| `in_data` | in | 16 | signed, Q1.15 |
| `in_valid` | in | 1 | continuous streaming (no back-pressure in v1) |
| `out_data` | out | 32 | signed, full-precision accumulator (16x18 products, 25 taps) — downstream rounds |
| `out_valid` | out | 1 | one pulse per two input samples |

Parameters: `IN_W=16`, `COEF_W=18` (DSP48E2 B-port width), `NTAPS=25` (odd, linear-phase symmetric), `DECIM=2`.
Coefficients: fixed at elaboration from a package (`fir_coefs_pkg.sv`), generated by `tools/gen_coefs.py` (scipy `firwin`, low-pass at 0.25 fs, Hamming).

## Architecture requirements

- Polyphase decomposition: even/odd phases, each phase runs at the input rate but only produces an output every 2 samples → compute at the **output** rate.
- Exploit symmetry `h[k] == h[24-k]`: pre-add the two samples sharing a coefficient before the multiply → **13 multipliers** (12 symmetric pairs + centre tap), not 25.
- Each pre-add + multiply + accumulate must map onto a DSP48E2 (pre-adder → multiplier → post-adder cascade). RTL coding style must let Vivado infer the pre-adder: `(a + d) * b` with registered `a`, `d`, `b`, product register, and an adder-chain (systolic) accumulate, not a tree.
- Fully pipelined, one new output every 2 clocks, constant latency (document it).

## Success criteria

- Lint clean (Verilator -Wall, Verible).
- cocotb test passes on Icarus and Verilator: impulse response equals the coefficient set, random-input output equals the scipy golden model (`scipy.signal.lfilter` + `[::2]`) bit-exactly, no overflow at full-scale input.
- Yosys `synth_xilinx -family xcup` stat: **DSP48E2 count = 13** (headline), LUT/FF reported; recorded as target-vs-actual in `.planning/HARDWARE_METRICS.md`.
- `synth/vivado_synth.tcl` + `synth/constraints.xdc` (300 MHz) delivered for the customer to run on a licensed Vivado: confirm DSP48E2 = 13 with pre-adders used, WNS ≥ 0.
- Honest caveat recorded: Yosys DSP inference approximates Vivado's; the Vivado run is the sign-off.
